━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Scan full text to identify all independent material variants/model systems.
   Whenever composition/formulation, processing state, test direction/configuration, component type, or hierarchical object changes, a new item must be created.

2. Generate stable Sample_ID for each item. Use the paper's own labels when available.

3. CRITICAL SPLITTING RULES (the #1 cause of extraction errors):

   MUST CREATE SEPARATE ITEMS for each:
   • Different heat-treatment temperature (e.g., 573K vs 673K vs 773K → each is one item)
   • Different annealing/aging time when it changes the microstructure
   • Different thermal exposure / oxidation durations (e.g., 50h, 100h, 150h, 200h → each is one item)
   • Different temperature×time combinations (e.g., 1400°C/50h, 1400°C/100h, 1450°C/50h → each is one item)
   • Different composition in a screening/parametric study (e.g., T01 through T17 → 17 items)
   • Different values in a single-variable parametric sweep (e.g., grinding speed 40/70/100/130/160/190/220/240 m/s → 8 items; laser power 5W/10W/12.5W/15W/20W → 5 items; sintering temp at 6 values → 6 items)
   • Different layers in a multilayer coating (Si layer, YbMS layer, LMA layer → each is one item)
   • As-built vs HIP vs aged vs annealed states on the same base alloy
   • Different ECAP passes or deformation states
   • Computational/simulation results → separate from experimental items (use Data_Nature: Computed)
   • Each (specimen_type × environment × method) in simulation studies → separate item (e.g., CT_air_sim, CT_air_exp, CT_H2_sim → 3 items)
   • FEM/thermomechanical models → separate items from experimental measurements
   • Phase-field simulations with different geometries/BCs → separate item per case
   • Oxidation kinetics model (parabolic rate constants, activation energies) → separate item
   • DFT/first-principles calculations → separate item per phase/composition
   • Phase-field / CALPHAD / Thermo-Calc / Arrhenius / JMAK fitted results → separate item
   • TEM/STEM-characterized specific interfaces with independent crystallographic data → separate items
   • Literature comparison data with specimen-resolved quantitative values → separate items (Role: Reference/Comparator)
   • Constituent materials / precursors / pure components with independent characterization (e.g., pure resin vs composite, monomer vs polymer, powder vs printed part)
   • In review papers: each reviewed material/case with quantitative property data → separate item
   • In software/method papers: each demonstration application case with measurable output → separate item

   MUST NOT SPLIT (keep as ONE item with multiple property entries):
   • Different measurement angles on the same sample (0°, 10°, 30° roughness → 1 item, 3 property entries)
   • Different surface positions on the same part (upskin/downskin → test condition in Property)
   • Different tensile test temperatures on the SAME unchanged specimen (RT, 400K, 600K tensile on same bar → 1 item)
   • Iterations of an optimization/active-learning algorithm that didn't produce characterized specimens
   • Pure bibliographic citations with no quantitative data (only author+year, no measurable values)

   KEY PRINCIPLE: condition changes that cause microstructural evolution (grain growth, phase transformation,
   oxidation, precipitate coarsening) → MUST split. Pure measurement parameters on same unchanged specimen → keep together.

   GRID COMPLETENESS RULE: If a paper studies a temperature×time matrix (e.g., 3 temperatures × 4 durations = 12 conditions),
   you MUST create ALL N×M items. Do NOT split some temperature levels while merging others.
   Count the matrix dimensions from tables/figures and verify your item count matches.

   PARAMETRIC SWEEP RULE: If a paper varies ONE process parameter across N values (e.g., speed at 8 values,
   power at 5 levels, sintering temp at 6 points), create N separate items — one per parameter value.
   Do NOT collapse to a single generic item. Each data point with measurable properties = 1 item.

   When a table has N rows with different processing conditions (temperature×time combinations), create N separate items.

4. Gradient materials are processed holistically first (Gradient_Material = true).
   Only split when the paper explicitly provides independent data for each layer, linked by Gradient_Group_ID.

5. Mark Role and Data_Nature for each item.
   - Target: main material synthesized/characterized in this paper
   - Variant: same composition as a Target but different processing state (e.g., different aging time, different thermal exposure duration)
   - Reference: literature comparison data from other papers with specimen-resolved quantitative values
   - Comparator: contrasting material/system compared against Target from literature (comparison table entries)
   - Demonstration: supporting FEM/simulation item that validates or illustrates a mechanism
   - Data_Nature: Experimental / Computed / Literature_Experimental / Literature_Computed

6. Record Raw_Evidence_Span for each item, preserving source text fragments that can locate the item.

7. Samples with different ratios/doping levels/modification treatments must each be independent items, even if composition differences are small (e.g., NVCOF vs PA_NVCOF vs ZVCOF).

8. Item-level routing field copy rule (mandatory):
   Each item's base_material / application / research_paradigm must directly copy the corresponding values from Paper_Routing.
   These are enum values (e.g., "Metals", "Structural", "Experimental"), free text or other formats not allowed.
   If an item belongs to a different material system (e.g., metal matrix in a composite paper), still use Paper_Routing's value at item level; explain difference in Note.

9. For active-learning / Bayesian-optimization / design-of-experiments papers:
   Only extract the FINAL validated/characterized specimens as Target items.
   Do NOT create items for every intermediate iteration proposal even if they have UTS/TE data.
   Specifically: if the paper ran N iterations selecting 2 candidates each (resulting in 2N total fabricated specimens),
   only extract the FINAL Pareto-optimal/recommended sample(s) that the paper highlights as key results.
   The initial training dataset (from literature) should NOT be extracted.
   Example: "5 iterations × 2 samples = 10 total" → only extract the 1-2 best/final specimens, not all 10.

10. Literature reference data extraction (comprehensive extraction principle, v10.5 enhanced):
   All literature comparison data appearing in the paper must be extracted as independent items (Role = Reference or Comparator), including:
   - Literature comparison data listed in tables with quantitative values (UTS, YS, elongation, hardness, coating life, oxidation rate)
   - Literature values mentioned in a single sentence (e.g., "The YS of Inconel 718 was reported to be 1100 MPa [15]")
   - Literature data points cited in figures (only when caption explicitly gives values)
   - Literature performance data cited in Discussion/Conclusion sections with quantitative values
   - Literature data in review comparison tables with specimen-resolved data
   Mark these items with Data_Nature='Literature_Experimental' (or 'Literature_Computed' for DFT/simulation literature).
   Do NOT extract pure bibliographic citations with no quantitative data (only author+year, no measurable values).
   **Active scanning strategy**: after completing Step F, additionally scan Discussion/Conclusion sections, searching for values near "[number]" citation markers, ensuring no omissions.

Extract composition information for each item, following faithful-to-source principle.

General procedure:
1. Identify composition representation (element percentages / stoichiometric formula / composite ratio / model system)
2. Strictly distinguish nominal vs measured composition, annotate Composition_Source_Type
3. Range values preserve original range; upper-limit values fill null and record source expression in Note
4. Standard deviation extracted to Value_StdDev
5. Specific field structures, naming rules, special constraints → see base supplement

Do NOT: normalize, back-calculate, infer composition from trade names.

6. Composition_Source_Type annotation rules (every item with composition data must annotate):
   Determination priority (top-down, stop on first match):

   ✅ nominal — source text explicitly uses "nominal" / "designed" / "nominal composition"
   ✅ measured — source text gives measured data with detection method noted (e.g., ICP-OES, EDS, XRF)
   ✅ nominal_inferred — composition appears in Experimental preparation description ("The alloy with composition...")
      but no detection results given → default type for most experimental papers
   ✅ measured_inferred — source text gives composition values with characterization method mentioned (e.g., "EDS analysis shows...")
      but doesn't explicitly use the word "measured"
   ⚠️ Only when none of the above four can be determined, omit the key (don't output null)

   Priority annotation principle: prefer marking nominal_inferred over omitting. 90% of experimental papers' compositions come from preparation formulations and should be marked nominal_inferred.

   Scenario examples (strict comparison):
   ✅ Paper gives composition table + explicitly mentions "EDS analysis / ICP-OES / XRF measurement" → measured
   ✅ Paper gives composition table without mentioning detection method, appears in Experimental section → nominal_inferred (default)
   ✅ Paper uses "nominal composition / designed composition" → nominal
   ✅ Paper gives composition values + mentions EDS characterization but doesn't say "measured composition" → measured_inferred
   ❌ Paper only mentions XRD characterization + gives composition table → nominal_inferred (XRD doesn't measure composition, shouldn't mark measured)
   ❌ Composition appears in preparation formulation but omits Composition_Source_Type → must annotate nominal_inferred
   ✅ Ceramic paper gives chemical formula + XRD phase analysis confirms phase composition → Composition_Source_Type not applicable at element level, omit; Phase_Composition annotated per XRD results
   ✅ Composite paper gives matrix/reinforcement ratio (e.g., "SiC fiber 40 vol%") → ratio preserved as source text, mark nominal_inferred as appropriate

11. Numeric form checklist (check item-by-item before output):
